# 错例对照表 —— 给格式审查 subagent 用

**用途**：机器审查（`_audit.py`）只能证明"尺寸和位置在数值上合规"，证明不了"看起来对"。
这个文件夹给**逐页人工/agent 审查**提供判据与参照。

**文件名里的代码对得上 `_audit.py` 的报错字样**，可直接筛选：

| 代码 | 对应 `_audit.py` 的输出 |
|---|---|
| `MIXED` | `pN MIXED formula scale …` |
| `IMG_SMALL` | `pN figure … only NNNpx wide` |
| `TABLE_FONT` | `pN table cell N.Npt < 10pt` |
| `BLEED` | `pN picture … bottom/right … > …` |
| `TEXT_SMALL` | ——（只查表内字号，正文字号要人工） |
| `NUM_MISSING` | ——（编号齐全性只能人工） |
| `OVERLAP` | ——（元素重叠只能人工） |
| `CHART_COLOR` | ——（配色和谐度只能人工） |

**怎么用**：审查时把待查页与这里的反例并排看。发现问题按
**页码 + 元素名 + 判据 + 期望值** 描述，不要只说"不好看"。

## 反例（应当被检出）

### 机器查得到（`_audit.py` 会报）

| 文件 | 现象 | 判据 |
|---|---|---|
| `反例-MIXED-公式倍率不一致.png` | 同一页两条**内容相同**的公式大小不同 | 两图的 `宽 / 原始像素宽` 之比必须相等。见 SKILL §5.3.1 |
| `反例-IMG_SMALL-图片太小.png` | 横构图插图只给 200px 宽，图内标注糊 | 插图宽 < 180px → problem；180–260px → 提示 |
| `反例-IMG_SMALL-图片太小（早期示例）.png` | 同一缺陷的早期实例：图文页插图只占栏宽 1/3（竖图塞进宽扁栏） | 同上 |
| `反例-TABLE_FONT-表格字号过小.png` | 表格 8pt | 表格字号 < 10pt → problem（投影不可读） |
| `反例-BLEED-正文溢出右边界.png` | 文本框宽 1400px > 正文区 1174px，文字越过 x=1227 | 正文右边界 ≤ x=1227。注：`_audit.py` 只对**图片**查出血，**文本框要人工查** |

### 只能人工查

| 文件 | 现象 | 判据 |
|---|---|---|
| `反例-OVERLAP-数字压住说明.png` | 大号数字压住下面的说明文字 | 大号数字段的 `ls` 必须 ≈1.05（默认 1.45 会让 50pt 行高 ≈97px 溢出预留框） |
| `反例-OVERLAP-数字压住说明（早期示例）.png` | 同上，早期版本 | 同上 |
| `反例-OVERLAP-文字压住图片（V1实例）.png` | 正文段落压到插图上方（真实踩过的坑） | 正文框底边必须低于其上方所有元素 |
| `反例-NUM_MISSING-图表缺编号.png` | 表无"表 N"、图注无"图 N"、公式无"(N)" | 编号齐全性：图 = 图 N，表 = 表 N，公式 = (N)，文献 = [N] |
| `反例-TEXT_SMALL-正文字号过小.png` | 正文 9pt | 正文 < 10pt。`_audit.py` 只查表内字号，正文要人工 |
| `反例-CHART_COLOR-图表配色未用主题色序.png` | 左：matplotlib 默认色（蓝/橙/绿/红）与绿金主调打架；右：`tokens.json` 的 `data-series` | 图表的分类色必须显式取自 `data-series` |

> 覆盖说明：`OVERLAP` 有 3 张（同一缺陷的当期版 + 两个早期实例）—— 这条最容易犯，
> 多留几个实例是有意的。其余缺陷各一张。

## 逐页审查：先机器，再人眼

```bash
cd build
python _audit.py                    # 数值类问题；退出码非 0 就不要交付
python _render.py ../out/seu_nari_template.pptx ../_preview/deck
python _contact.py ../_preview/deck ../_preview/sheet.png 3 560
```

**两类结论要分清**：

- `_audit.py` 的 **problem 必须修**（退出码非 0 就别往下走）。
- **advisory 是提示不是错误**（占位框底边、图偏小之类）——发给 reviewer 时要说清哪类是哪类，
  否则会把噪声当缺陷报上来，也会漏掉真正该看的东西。

**机器查不到、必须人眼看的**：编号齐全性、元素重叠、图"数值达标但仍显小"、
公式同页/相邻页是否一样大、中文标点与断行、图表配色。

## 多 agent 交叉审查（长 deck 用）

1. 把页分成**有重叠**的区间，例如 `0–20 / 10–30 / 20–40 / 30–50`。
   重叠 10 页用来交叉验证 —— **两个 agent 都漏报的页**才最可能真没问题。
2. 每个 subagent 拿到：**本文件夹**、它的那一段页图、`SKILL.md §7.2` 的检查清单。
3. 要求按 **页码 + 元素名 + 判据 + 期望值** 回报。
4. 汇总时**优先修多个 agent 都报的**；只被一个报的先回看确认。

**按区间出图不用手工切 PNG**：

```bash
python _contact.py ../_preview/deck ../_preview/slice_10_30.png 3 560 10-30
```
